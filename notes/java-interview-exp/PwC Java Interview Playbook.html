Round 1 · foundations that invite follow-ups

Start narrow. Go deep.

The opening questions were “introduce yourself”, “explain your project”, and “which Java versions have you used?” The version question is a doorway, not a trivia check.

1

A safe answer shape

“I work primarily with Java 17 in my current service. I use records for compact DTOs and the Stream API for collection transformations. Before that, I used Java 8 features such as lambdas and Optional.” Only name features you can explain with code.

Java 8 essentials

Know the tools and the reason

Lambdas pass behaviour as a value. Functional interfaces define its shape. Streams transform data declaratively. Optional makes absence explicit. The Date/Time API avoids mutable, timezone-confused legacy dates.

Classic trap

Can a functional interface extend two others?

Yes—only when the inherited abstract methods collapse to one logical signature. If the parents introduce different abstract methods, it is no longer a functional interface and compilation fails.

List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6);

List<Integer> evens = numbers.stream()
    .filter(n -> n % 2 == 0)
    .toList();

int evenSum = numbers.stream()
    .filter(n -> n % 2 == 0)
    .mapToInt(Integer::intValue)
    .sum();

Talk through the code: “The filter keeps only even values. For the sum, I use an IntStream so I can call sum() without boxing.” That narration proves you understand the pipeline.

Why do we need lambda expressions?

Pause for 20 seconds. Give a reason, not a definition.

Model answer: Lambdas let us pass small behaviour to a method without an anonymous class. They work with functional interfaces and make transformations such as filtering, mapping, and sorting shorter and easier to compose. I use them most often in Stream pipelines and callbacks.

Can an @Bean method be private?

Explain the proxy issue, then state the exception.

Model answer: In a normal proxied @Configuration class, Spring enhances the configuration class so inter-@Bean calls can return managed singletons. Private methods cannot be overridden, so avoid private @Bean methods there. With proxyBeanMethods = false / non-configuration “lite” mode, those cross-method calls are not intercepted—use dependency injection instead.

Can a transaction commit after an exception?

Say the default, then name two ways the result can change.

Model answer: Yes. Spring’s usual default rolls back for RuntimeException and Error, not checked exceptions. It may also commit if an exception is caught and not rethrown. I make the intended behaviour explicit with rollbackFor when appropriate, and I verify the real outcome with an integration test.

Round 2 · your project under load

Make the request flow visible

This round tested whether the candidate had actually built and operated the system: security, logging, performance, data access, service communication, and deployment recovery.

Project walkthrough

Use a request narrative

Start at the client. Name the gateway or controller, authentication, validation, service decision, database or downstream call, emitted event, response, logging, and metrics. This makes follow-up questions easy to handle.

Security + errors

Be concrete, not generic

Name your authentication mechanism, authorization rule, how secrets are supplied, the correlation ID, structured error log fields, alert condition, and what you deliberately do not log—tokens, passwords, or sensitive personal data.

When concurrent traffic rises

MeasureLatency, error rate, throughput, saturation.
Scale safelyStateless instances behind a load balancer.
Protect dataTune DB pool; index real query paths.
Cache wiselyCache stable, read-heavy data with expiry.
DecoupleMove slow, non-critical work to async messaging.

Interview upgrade: Do not jump straight to Redis or Kafka. First say what is slow and how you know: “The dashboard shows database connection-pool wait time, so I’ll inspect slow queries and pool saturation before adding a cache.”

Thousands of MySQL rows

Paginate or use cursor/keyset pagination; select needed columns; add indexes matching the actual WHERE/ORDER BY; consider projections and caching.

Need an answer now

Use synchronous communication when the caller truly needs the response—e.g. validating a user or pricing a request. Bound it with timeouts, retries only where safe, and fallbacks.

Event can happen later

Use asynchronous messaging for notifications, analytics, or background work. Design for retries, duplicates, dead letters, observability, and idempotent consumers.

Deployment incident answer

2

Find the slow stage before “fixing” it

“I compare build, test, image creation, image push, and rollout durations with prior deployments. Then I check recent changes: dependency growth, Docker-layer cache misses, image size, registry speed, startup time, readiness failures, and cluster capacity. If impact is high, I roll back to the last known-good version while I investigate.”

How should I answer “how do you deploy and recover from failure?”
Describe your real pipeline. Mention checks before deployment, health/readiness probes, logs and metrics during rollout, a rollback path, and a short post-incident improvement. Never claim blue-green or canary deployment if you have not used it; explain how you would use it instead.
What does “stateless service” mean in this answer?
Any request can go to any instance because user/session state is not stored in that instance’s memory. Persistent state lives in a shared backing store such as a database, cache, or identity provider. That makes horizontal scaling and replacement safer.

Coding drills · simple logic, clear narration

Write the straightforward solution first

The transcript included stream questions and an anagram task. Your interviewer is usually watching your assumptions, complexity, naming, and tests—not only the final answer.

Before typing

Ask one useful question

“Should comparison ignore case and spaces?” “Can input be null?” “Are characters limited to lowercase English letters?” Then say the complexity before you code.

After typing

Walk the edge cases

Empty strings, different lengths, repeated letters, casing, punctuation, and a quick happy-path example. Then offer tests rather than silently hoping it works.

boolean areAnagrams(String a, String b) {
    if (a == null || b == null || a.length() != b.length()) {
        return false;
    }

    int[] counts = new int[26]; // lower-case a-z assumption
    for (int i = 0; i < a.length(); i++) {
        counts[a.charAt(i) - 'a']++;
        counts[b.charAt(i) - 'a']--;
    }
    for (int count : counts) {
        if (count != 0) return false;
    }
    return true;
}
boolean areAnagrams(String a, String b) {
    if (a == null || b == null || a.length() != b.length()) {
        return false;
    }
    return a.chars().boxed()
        .collect(Collectors.groupingBy(
            Function.identity(), Collectors.counting()))
        .equals(b.chars().boxed()
            .collect(Collectors.groupingBy(
                Function.identity(), Collectors.counting())));
}

Complexity: both approaches are O(n) time. The frequency-array version uses constant space for its stated alphabet. The map/stream version is more general, but it has more allocation and is less appropriate if the interviewer explicitly asks for only basic logic.

Round 3 · live coding + technical management

Build a small API like it will be reviewed

The live task was an Employee–Address CRUD API, with proper responses, exception handling, and a find by city follow-up. A clean shape matters more than a huge solution.

Say this before coding: “I’ll first make a thin vertical slice: DTO, validation, service, repository, and exception handler. I’ll return a response DTO, then add the city search with pagination. If time remains, I’ll add tests and discuss indexes and relationship fetching.”

Before opening a pull request

Quality

Evidence, not confidence

Run tests, inspect the changed API contract, check validation and error paths, look for N+1 queries, review logs for sensitive data, format/lint, keep the diff small, and write a PR description that explains why.

Conflict

Requirements vs best practice

Clarify the business constraint and risk. Offer options with cost, security, and delivery impact. Record the decision. Escalate only when necessary; do not frame it as business versus engineering.

Managerial + HR · keep it truthful and forward-looking

Make your career story coherent

The final question—“why are you looking for a change?”—is not an invitation to criticise your employer. It checks maturity, direction, and whether the move makes sense.

“I’ve built strong experience in [your real area] and I’m proud of [specific impact]. I’m now looking for a role where I can deepen [skill/domain], take more ownership of [scope], and work on [genuine attraction to the role]. This position fits that direction.”

Never invent production stories. If you have not owned a deployment, say what you observed, what you contributed, and how you would approach the decision. Honest depth beats broad, fragile claims.
