One abstract method is the contract

A functional interface has one abstract method: a SAM (Single Abstract Method). A lambda supplies the implementation of that method inline.

The contract

Custom interfaces are useful when the domain needs a name

Validator<T>, PriceRule, or RetryPolicy can make business intent clearer than a generic Predicate or Function.

Safety net

@FunctionalInterface is optional—but valuable

The annotation is a compiler check. Default and static methods are allowed because they already have bodies; only abstract methods count toward the SAM rule.

@FunctionalInterface
interface Validator<T> {
    boolean isValid(T value);
}

Validator<String> notBlank = text -> text != null && !text.isBlank();
Validator<Integer> positive = number -> number != null && number > 0;

System.out.println(notBlank.isValid("Java")); // true
System.out.println(positive.isValid(-3));     // false

Interview trap: an interface may extend multiple interfaces, but it is functional only if all inherited abstract methods resolve to one logical method signature. Different abstract methods mean it is not a lambda target.

The four shapes worth memorising

Do not memorise a long list first. Identify input → output. The method name then becomes predictable.

Streams connection

Read Stream operations by their shape

map takes a Function, filter takes a Predicate, and forEach takes a Consumer. Once you see the shapes, the API stops feeling arbitrary.

Supplier commonly appears in lazy creation, factories, and APIs such as Optional.orElseGet.

Primitive specialisations: avoid unnecessary wrappers

Generic interfaces work with objects, so Function<Integer,Integer> represents primitive values as Integer. For performance-sensitive numeric pipelines, Java provides primitive shapes such as IntFunction and IntSupplier.

Use the generic form when

Readability matters more than tiny per-element costs, values are objects anyway, or the code is not a hot numeric path.

Reach for primitive forms when

You are working repeatedly with int, long, or double values—especially in tight data processing. Profile before declaring a bottleneck.

IntBinaryOperator sum = (left, right) -> left + right;
IntUnaryOperator doubleIt = value -> value * 2;
IntSupplier dice = () -> ThreadLocalRandom.current().nextInt(1, 7);

System.out.println(sum.applyAsInt(3, 4));     // 7
System.out.println(doubleIt.applyAsInt(5));   // 10
System.out.println(dice.getAsInt());          // 1 through 6

Method references say “call that method”

Use a method reference when a lambda only delegates to an existing method. It is not automatically better—prefer it when it makes the code easier to read.

StaticMath::absx → Math.abs(x)
Bound instanceSystem.out::printlnx → System.out.println(x)
Unbound instanceString::isBlanks → s.isBlank()
ConstructorArrayList::new() → new ArrayList<>()
How do I recognise an unbound instance reference?
The lambda parameter becomes the receiver: s -> s.isBlank() is String::isBlank. By contrast, System.out::println is bound because System.out is already a specific object.

Composition: make small functions cooperate

For functions, values flow from one step to the next. andThen reads left-to-right; compose installs a step before the current function.

f(x) = x + 2 · g(x) = x × 3
f.andThen(g) = g(f(x))215 → 7 → 21
f.compose(g) = f(g(x))175 → 15 → 17
Function<Integer, String> label = n -> "value=" + n;
Function<String, String> shout = String::toUpperCase;

Function<Integer, String> pipeline = label.andThen(shout);
System.out.println(pipeline.apply(5)); // VALUE=5

// The types chain: Integer → String, then String → String.

Type rule: for f.andThen(g), the output of f must be compatible with the input of g. This is why Integer → String can be followed by String → String, but not by a function that expects an Integer.

Predicate logic

Same input; boolean rules combine

positive.and(even) means “both are true”. Use or and negate for the other boolean combinations. Predicate composition short-circuits just like && and ||.

Consumer sequence

Same input; effects run in order

log.andThen(save).accept(order) passes the same order to both consumers. There is no transformed value to feed forward; if the first throws, the second does not run.

Two inputs: use the Bi family

When behaviour needs two inputs, use BiFunction<T,U,R>, BiConsumer<T,U>, or BiPredicate<T,U>. There is no BiSupplier: a supplier intentionally takes no input.

BiFunction<Integer, Integer, Integer> gcd = (a, b) -> {
    while (b != 0) {
        int remainder = a % b;
        a = b;
        b = remainder;
    }
    return Math.abs(a);
};

BiPredicate<Integer, Integer> coprime =
    (a, b) -> gcd.apply(a, b) == 1;

System.out.println(coprime.test(8, 15)); // true
Real API clues

Spot them in the JDK

Map.forEach takes a BiConsumer<K,V>. Map.merge combines values with a BiFunction. BiFunction.andThen can transform its result; it has no compose, because composing “before” it would need to manufacture two inputs.
